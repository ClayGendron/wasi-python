## The facts

**What fails.** `sklearn/utils/_repr_html/estimator.py` builds `_CSS_STYLE` when it is imported
(line 29), by reading `estimator.css`, `params.css` and `features.css` from
`Path(__file__).parent` (lines 15-24). `sklearn/base.py:24` and `sklearn/utils/__init__.py:19`
import the module, so every import of scikit-learn runs those reads. When scikit-learn's Python
files are imported from a zip archive (by `zipimport`, from `sys.path`), `__file__` is a path
inside the archive, and its parent is not a directory. In a model of that layout on macOS
(tool output, `evidence/native-run.txt`, item 1):

```
import sklearn -> NotADirectoryError pure-stock.zip/sklearn/utils/_repr_html/estimator.css'
```

`estimator_html_repr` also opens `estimator.js` by the same path (line 563 in 1.9.1).

**Where this matters.** Any layout where scikit-learn's Python is not plain files on disk:
a zip on `sys.path`, a frozen or bundled application, an importer that serves files from memory.
This project runs CPython on `wasm32-wasip1` with the packages' Python in the standard library's
zip and the extension modules linked in.

**The change** (`fix.patch`, 1 file, +8 −10). The three style sheets and the script are read
with `importlib.resources.files(__package__).joinpath(name).read_text(encoding="utf-8")`, which
reads a file on disk and a member of an archive alike. `pathlib.Path`'s import is dropped, since
nothing else in the module uses it. One detail changes: in 1.9.1 `estimator.js` is read in the
locale's encoding (`open(..., "r")`); it holds two `✔` characters, so it is UTF-8, and the change
reads it as UTF-8, as `main` already does. Under UTF-8 mode (the default from Python 3.15) the
text is the same either way.

**How it was tested** (EXECUTED 2026-10-18, `evidence/native-run.txt`):
- with the change, from the zip model, `import sklearn`, `import sklearn.base` and an estimator
  import succeed (item 2);
- `estimator_html_repr` of a `StandardScaler` and `LogisticRegression` pipeline gives the same
  55,811 characters, with the same digest, from the patched zip as from the stock package on
  disk (the id counters normalised); `all_estimators()` finds 208 in both (item 3);
- a 30-line program that fits and scores a dozen estimators on the bundled datasets prints the
  same bytes natively and from the patched zip (item 4; `evidence/machine_learning-draft.py`).

**A test you could add.** scikit-learn's suite has no zip-import test. One that copies
`sklearn/utils/_repr_html/` into a zip, imports `estimator` from it under another package name,
and checks `_CSS_STYLE` holds a line of `estimator.css`, fails before the change and passes
after; writing it in scikit-learn's test conventions is yours.

**Alternatives a reviewer may raise.**
- *Read the files lazily, on first HTML repr.* That stops the import failure but leaves
  `_repr_html_` failing in the same layouts; the resource read fixes both.
- *`pkgutil.get_data`.* It works too; `importlib.resources` is what scikit-learn's datasets
  already use (`sklearn/datasets/_base.py`).
