## The facts

**What fails.** With networkx imported from a zip archive, `graph_atlas(i)` and `graph_atlas_g()` raise (tool output):

```
  File ".../networkx/generators/atlas.py", line 63, in _generate_graphs
    with gzip.open(ATLAS_FILE, "rb") as f:
TypeError: filename must be a str or bytes object, or a file
```

It reproduces on any CPython with the stock wheel on `PYTHONPATH`, since a wheel is a zip that zipimport reads. EXECUTED on CPython 3.15.0 with networkx 3.7 (`context/upstream/6-networkx-atlas-from-a-zip/evidence/networkx-native.txt`):

```
PYTHONPATH=networkx-3.7-py3-none-any.whl python -c "import networkx as nx; nx.graph_atlas(6)"
```

**Why, and the history.**
- networkx#3929 ("Consider removing dependency on `__file__`", raised for PyOxidizer) asked networkx to stop finding its data files through `__file__`.
- networkx#6936 ("MAINT: Use importlib.resources instead of file dunder to access files", merged 2023-09-23, closing #3929) made the change: `ATLAS_FILE` became `importlib.resources.files("networkx.generators") / "atlas.dat.gz"`.
- That value is a `pathlib.Path` only when networkx is installed as files. From a zip archive it is a `zipfile.Path` (or another `Traversable`). It has no `__fspath__` and no `read`, so `gzip.open` refuses it.
- The one-line fix completes what #6936 set out to do: the data file is read through the resource API, however networkx is installed.

**The change** (one line, plus a two-line comment). Open the resource with its own `open`, and give `gzip.open` the file object:

```python
    with ATLAS_FILE.open("rb") as raw, gzip.open(raw, "rb") as f:
```

`Traversable.open("rb")` is part of the `importlib.resources` API, so this works for a path and for any resource reader. `ATLAS_FILE` keeps its value and type, so nothing changes for backward compatibility. One point to review with care: the comment above `ATLAS_FILE` still calls it "the absolute path" of the file. You may want to reword it as "the resource".

**The test** is in the patch. `test_atlas_file_in_a_zip`:
1. writes `atlas.dat.gz` into a zip under `tmp_path`;
2. points `atlas.ATLAS_FILE` at a `zipfile.Path` in that zip, with `monkeypatch`;
3. checks `graph_atlas(6)` the way `test_graph` does.

**How it was tested** (EXECUTED 2026-10-17):

- **The generators' tests.** On the line's CPython 3.15.0 with numpy and pandas installed (the pre-build review), `networkx/generators/tests` gives 614 passed and 18 skipped.
