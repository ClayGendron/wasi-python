- **Title:** BUG: use the file-like path for .npy files on WASI
- **Files:** numpy/lib/_format_impl.py, numpy/lib/tests/test_format.py
- **Why we carry it:** `np.save` to a path and `np.load` of a path raise `OSError` 58 in the guest, because `tofile` and `fromfile` call `os.dup`, which WASI cannot do.

One behaviour to state in the description: the public `numpy.lib.format.isfileobj` now returns False on WASI for real files, so callers on WASI take the chunked path, as they already do for other file-likes.

Amended 2026-10-18 (spec 051, Decision 10; not yet sent, so amended in place). Three more points for the description, each in the facts (`../../3-numpy-npy-wasi/pr.md`, "The amendment"):

- **One predicate and the subclass rule.** Native `isfileobj`'s two tests (the `isinstance` and the `fileno()` probe) become a private `_is_real_file(f)`, and `isfileobj(f)` is `_is_real_file(f) and sys.platform != "wasi"`. In `write_array`, on WASI, a real file and an array whose type overrides `tofile` go to that `tofile`, as on other platforms: a masked array saved to a path raises `MaskedArray.tofile`'s `NotImplementedError` instead of being written without its mask. The new test `test_save_masked_without_dup` holds it, with a `BufferedWriter(BytesIO())` that is written in chunks, as natively.
- **A truncated real file's message on WASI.** A real file is read the way numpy reads an in-memory stream, so a truncated one raises numpy's in-memory `ValueError` ("EOF: reading array data, expected 48 bytes got 47"); the type is native's.
- **`test_file_truncated`** therefore accepts that message too, behind `sys.platform == "wasi"`, so it passes on WASI once the change is in.
