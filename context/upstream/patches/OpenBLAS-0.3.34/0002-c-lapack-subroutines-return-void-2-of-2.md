- **Why we carry it:** on `wasm32-wasip1` a call whose signature differs from its definition's traps, and 0.3.34's C LAPACK declares the same subroutines both `int` and `void`; upstream `develop` made them all `void` after the release.

**Nothing to send.** OpenBLAS's `develop` branch already carries this convention: every
subroutine of its C translation of LAPACK returns `void`, as LAPACK's Fortran subroutines do, and
`xerbla_` takes f2c's hidden string length everywhere. It was merged as the series #6008, #6017,
#6022, #6030, #6036, #6049, #6061, #6063, #6077, #6079, #6080, #6081 and #6082 (read on `develop`
at `0fee0ebe`, 2026-10-17; `context/research/2026-10-17-openblas-one-return-convention/outputs/upstream-develop-void.txt`),
after 0.3.34 was released.

This patch is not upstream's diff. It reaches the same convention on the pinned 0.3.34 tarball by
this project's own script, `scripts/openblas_make_void.py` (rules R1 to R6, in its header), and
`scripts/make_openblas_void_patch.sh` writes it with plain `git diff` under a cleared git
configuration, so any reviewer regenerates it byte for byte; `scripts/audit_openblas_void.py`
pairs every changed line with one of the rules (spec 037, Decision 5). The convention's one diff
is 1,119,076 bytes, over the repository's 1 MiB limit for a tracked file, so it is carried as two
patches cut at a file boundary (0001: every file before `lapack-netlib/SRC/s`; 0002: the rest);
concatenated, the two are that one diff (SHA-256 `c8f96665…7eaac`).

Why it is carried: on `wasm32-wasip1` a function called with another signature than its
definition's traps, and wasm-ld links a trapping stub for a direct call whose type differs. 0.3.34's
C LAPACK mixes `int` and `void` returns for the same subroutines: 111 such clashes when the
archive is linked whole (step 38's link-whole gate; EXECUTED, `build/037/seen-failing-38-unpatched.log`),
0 with the patches.

It is deleted, and the pin moved, when OpenBLAS releases 0.3.35 with the convention.
