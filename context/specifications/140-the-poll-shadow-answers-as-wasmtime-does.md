## The problem

`_poll_plan` (`_call.py:1082-1114`) says it answers "as wasmtime 49 answers it", and in four ways it does not (EXECUTED by h14, 12 cases against wasmtime's own and 55 against the shadow; READ here).

- It accepts misaligned `in_ptr`, `out_ptr` and `nevents_ptr`, which wasmtime ends the run for.
- It accepts unknown `subclockflags` bits, which wasmtime answers `EINVAL`.
- It reports any descriptor other than 0 to 3 ready with nbytes 1, where wasmtime answers `EBADF` for a descriptor that does not exist or is a folder; a run preopens more than one folder, so 3 is not the only preopen.
- `_poll_oneoff.call`'s `except Exception: return EINVAL` (`_call.py:1171-1172`) would swallow a `WasmtimeError` from `_fs_memory._ends` into `EINVAL`, so the alignment fix cannot be written inside today's handler (READ, the review's Low 9).

No memory effect: every write stays in the checked region. The out-pointer bound uses `32*n`, stricter than wasmtime's `32*len(events)`; kept. And h14 shows wasmtime ending the run for an out-pointer with no room, where the shadow answers `EFAULT` (READ, `compare_wasmtime.json`): a difference this specification keeps (Decision 4).

The draft's descriptor rule, "a number the table does not hold, or a folder, answers `EBADF`", had no way to know wasmtime's own descriptors (READ, the review's High 1). The call's table holds only the mounts' entries (`table`) and the numbers of what wasmtime opened (`held`), never their kind (`_fs_table.py:97-134`). Every file the guest opens on a plain grant or on the zip is wasmtime's descriptor, so the rule as written would answer `EBADF` for every such file, where wasmtime and today's shadow both answer ready: a guest that opens `/data/x.txt` on a read-only grant and polls it for reading would get `EBADF` on a path that works today.

## Decisions

### 1. Misaligned pointers end the run

`in_ptr % 8`, `out_ptr % 8` and `nevents_ptr % 4` nonzero end the run through `_fs_memory._ends`, as the mount shadows do. The check comes after the `n == 0` and `n > MAX_SUBSCRIPTIONS` answers, as wasmtime checks the count first, and before the bounds, so a misaligned pointer past memory ends the run as wasmtime ends it. Reason: wasmtime ends the run for them (h14), and `_ends` is the runner's one way to give a guest wasmtime's ABI end.

### 2. Unknown clock flags are `EINVAL`

`flags & ~ABSTIME` nonzero answers `EINVAL`. Reason: wasmtime answers it so (h14), and today's shadow ignores the bits.

### 3. A descriptor is answered from what the runner knows

A descriptor subscription is answered from what the runner knows, in this order: a number in the table's `held`, ready; 0 to 2 as today; a preopen's number (3 up to 3 plus the call's preopens) and a mount's folder `EBADF`; a mount's file ready; any other number `EBADF`. `_poll_plan` takes a `kind(fd)` argument, so the unit rows stay pure. A folder the guest opened through `path_open` is held, and is answered ready where wasmtime answers `EBADF`: a kept difference, said in the docstring, since the runner does not ask wasmtime a descriptor's kind. With no table, which only the judge's stand-ins build, the poll answers every number above 2 ready, today's answer.

Reason: the call already knows every number the guest can hold, by the counted calls, and asking wasmtime a held number's kind would mean a forward of `fd_fdstat_get`, which writes into guest memory, or tracking `path_open`'s flags; neither is worth one poll answer for a folder, which no working program polls. `held` is read first, before 0 to 2 and the preopen numbers, so a file the guest renumbered onto 1 or onto a preopen's number (`_renumbered` moves it into `held`, READ, `_fs_table.py:594-599`) is ready, as wasmtime answers it (EXECUTED by the pre-build review's probe: a file renumbered onto 1 is ready for reading, nbytes 1, and one renumbered onto 3 is ready). The `kind` comes from one `_Files` method in `_fs_table.py`, and `_poll_oneoff` takes the call's table as a required keyword argument `files`, given where `_Call.__init__` builds `self.poll`, and answers descriptors through `files.kind`. The preopen count is `len(others)` in `_Files.__init__`: the guest paths of every preopen that is not a mount's, HOME and the zip included, in the order wasmtime numbers them from 3; the mounts' own preopens are in `table` with `preopen=True` (READ by the review, `_call.py:472-486` and `_sessions.py:1010-1024`).

### 4. The poll's own errors, and the differences kept

`call` re-raises a `WasmtimeError` before its `except Exception`, and, when `files.metered`, sets `files.stop_fuel = (error, ffi.get_fuel(caller))` before it re-raises, as `_Files.__call__` does for an ABI error. Six differences are kept, each named in the docstring with wasmtime's answer and the shadow's, and asserted as the shadow's own answer: an in-pointer or out-pointer past memory (wasmtime ends the run, the shadow answers `EFAULT`); the out-pointer bound (wasmtime's is `32*len(events)`, the shadow's `32*n`); a folder the guest opened through `path_open` (wasmtime `EBADF`, the shadow ready; Decision 3); the cap of 4096 subscriptions (wasmtime has none and answers 0 with room for every event, the shadow `ENOMEM`; the cap bounds one call's host work); the event's padding (wasmtime writes the event's fields only and leaves its 11 padding bytes as they were, the shadow writes them as zeros); and a closed 0, 1 or 2 (wasmtime `EBADF`, the shadow ready, as today, since the counted `fd_close` does not track stdio). Reason: the re-raise goes to the shared function, which records it as the call's stop, as every `_ends` error does (READ, `_fs_memory.py:185-193`); the fuel then is the guest's, as for a mount shadow's ABI error (READ, `_fs_table.py:268-278`), and without the record a metered run that ends on a misaligned poll reports fuel `None`, since `call.stopped` is set (READ, `_call.py:560-569`). The six are kept because each lets the guest do nothing wasmtime refuses it: every write stays in the checked region, and a read or write on a closed or folder number still gets wasmtime's own answer; a row asserts each, so none is "fixed" into a weaker answer later.
