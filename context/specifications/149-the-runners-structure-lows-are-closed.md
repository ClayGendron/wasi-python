## The problem

Seven small faults, each named by a review or a run, none of which a rules check catches today.

## Decisions

### 1. A resolve-once table is published whole, in one assignment, with no lock

Each of the four fills (`_Linux._stack_bounds`, `_Darwin._access_list`, `_Darwin._stack_bounds`, `_Windows.stack_bounds`) builds its table in a local dict and binds it to the platform object's attribute in one assignment once every key is in it. The attribute starts as `None`, not `{}`: `self.stack_api: dict[str, Any] | None = None` and `self.acl_api: dict[str, Any] | None = None`. A fill reads the attribute once into a local, builds when it is `None`, publishes, and then uses only its local. A reader therefore sees `None` or a whole table, never a part. Two threads that both find `None` both resolve, each uses its own, and the last assignment wins. `kernel32`'s `win_api` and both `identity` dicts keep their shape: each binds one key whose value is whole. The same comment on each attribute says so: published whole, read once into a local.

Reason. The fill is idempotent: resolving a C function by name has no effect beyond the lookup, and two resolutions of the same name are interchangeable. So the only fault is that a partial table is visible, and a single attribute store, which is atomic in CPython with or without the GIL, removes it with no lock. A lock is worse here. `_process.py`'s lock order (`:10-29`) names no lock whose job this is. Borrowing `cache_lock` would nest it under a module's `compiling` guard (`_access_list` runs inside `_module_miss`, under the guard at `_engines.py:180`), a pair the order does not name. A new lock would be a lock-order amendment and make this specification structural. The roadmap's reserved line said "filled under a lock"; the reviewer offered both, and this one needs neither a lock nor an amendment. Today a caller sees `KeyError: 'free'` out of `run()` on macOS, and a refused call on every system; after this, neither.

### 2. The stop is recorded through the table's own method, and the poll shadow is a table handler

`_Files` gains `record_stop(error, caller)`: on a metered table it sets `stop_fuel` to the error and the guest's fuel read from `caller` now; on an unmetered one it does nothing. `_Files.__call__`'s ABI branch (`_fs_table.py:271-279`) calls it, and so does the poll shadow (`_call.py:1146-1151` becomes one line, `files.record_stop(error, caller)`). `_Files.forward` keeps its own line (`_fs_table.py:264`): it is the table's own method and records the fuel it already holds, `before`, which it has just set back. `TABLE_HANDLERS` gains `_call.py`, and its comment says that the poll shadow receives the table as `files` too.

Reason. This is the reviewer's fix. Adding `_call.py` to the rule is what keeps it fixed: the next shadowed call outside `_fs_*` that writes a table field is red by name. The rule already finds exactly the one write in `_call.py` and nothing else there, so the tuple can grow by one file without an allowance.

### 3. Callers reach the platform's shared helpers through `_platform`, and a rule check holds the door

`_platform.py` gains three delegates of `_platform_common`'s helpers: `_rewritten_on_windows(name)`, `_owned_by_this_user(st)` and `_remove_file_quietly(path)`, each one line that calls `_platform_common._rewritten`, `_this_users` or `_unlink_quietly` at the call. They are delegates, not the `from ._platform_common import … as …` form 131 used for `Identity` and `_Walked`, because two package rules refuse that form for a function: `tests/unit/test_runner_package.py::test_a_module_imports_by_name_only_what_never_changes` (a function is reached as `_x.name`, so a stand-in set on its module is seen) and `::test_every_runner_name_is_defined_in_one_module` (so each delegate has a name of its own). `_zip.py` and `_private_dirs.py` import `_platform` alone and call the three delegates. A new check in `tests/checks/test_rules.py`, `test_only_the_platform_modules_import_its_halves`, reads `scan.sibling_imports` over every module of the package and refuses an import of `_platform_common` outside `_platform.py` and `_platform_windows.py`, and of `_platform_windows` outside `_platform.py`, at any depth and under `TYPE_CHECKING` too.

Reason. The reviewer's first fix, and 131's own rule (`131-the-platform-module-is-split.md:70`). Methods on `PLATFORM`, the reviewer's other option, would move two pure functions onto the platform object for no gain: neither differs by system. The check is the half that keeps it: 139 placed its names by the rule and still called them past the door, because nothing refused it. The Windows clause repeats part of `test_the_platform_is_chosen_once` on purpose, so the new check states the whole door in one place.

### 4. The poll and the call require their table

`_poll_oneoff`'s `files` is required and typed as a protocol declared beside it in `_call.py`, `_PollFiles`, with two methods: `kind(fd)` and `record_stop(error, caller)`. `_Files` meets it as it stands. The default answer for `None` (`_call.py:1115-1118`) goes. The two rows that passed `files=None` pass a two-method stand-in that answers `kind` as the removed default did (`None` for 0 to 2, `"held"` past them) and records each `record_stop`. Because `_Call.__init__` passes its `table` to the poll, `_Call`'s `table` becomes required and keyword-only, and the branches that read a missing table go: `_fuel_used`'s (`:561`), `_drive`'s (`:613`), `_Call.files`'s (`:695-696`) and `_context_of`'s `None` case (`:834`; its `isinstance` test for a judge's fake context stays). The three rows that built a `_Call` with no table build the table `_call.run` builds for a call without mounts (`_call.py:494-504`: no mounts, the call's preopens as `others`, a `_Context`), and the two production sites and `tests/harness/files.py` pass `table=` by keyword.

Reason. The reviewer's fix: "have the judge's poll stand-ins build a real `_Files` or a one-method `kind` protocol, so that `files` is required", with the second method Decision 2 gives it. `_Call`'s table follows from the type: `mypy --strict` refuses a `_Files | None` passed where a `_PollFiles` is required, and the alternative, a stand-in table built inside `_Call` when none is given, would be the same judge-only branch moved one function up. Production behaviour does not change: both production sites already pass a table (`_call.py:505`, `_sessions.py:668`). L4's other half, the owner test's observer, is not done here (Scope).

### 5. The reader's fall to its slow loop is reported, and the descriptor row asserts it never happened

`_Observers` gains `on_slow_loop: Callable[[str], None] | None = None`, after `on_capture`, with the comment "each fall of a pipe reader to its slow loop: the failure's type name". `_drain`'s `except BaseException` calls it with `type(e).__name__` before it enters `_slow()`, inside a `try` whose `finally` enters `_slow()`, so an observer that raises cannot stop the reader. The child program of `test_output_arrives_above_descriptor_1024` sets the observer to a list's `append` and prints the list; the row asserts it is empty. The child of `test_a_reader_whose_wait_fails_still_reads_every_byte` does the same and the row asserts `["OSError", "OSError"]`: the call's reader and the session's, each once.

Reason. The reviewer's first fix (an observer on the process object, as `on_capture` is) rather than its second (a count in `stats()`), because `stats()` is public API and a fall is a fact for the judge, not for an embedder: the reader still delivers every byte after one. The positive row proves the observer fires, so the empty list in the descriptor row means `poll` read every byte.

### 6. `dropped` is set where a piece is lost or may be lost to its turn, and nowhere else

A failed `os.read` in `_take` no longer sets `dropped`. It adds its end to a set on the capture, `self.failing`, and raises as today, so the reader moves to its slow loop. The next read of that end that does not raise (bytes, end of file, or nothing ready) removes it. Where the reader answers a settle (`_slow`, before `settled.set()`) and where it ends (`_end`), each end still in `failing` sets `dropped` on its stream's current target, since what that end held may not have been read before the turn's streams were handed back. A piece the stream fails to keep stays as it is: `dropped` (`_outputs.py:229-232`). `_take`'s docstring and the module docstring's reader rules say so. The callback capture's rule is 144's Decision 5 and is not touched here.

Reason. The reviewer's fix, "set `dropped` only where a piece is lost", applied so that it cannot under-report. A failed read loses nothing only if the end is read again before its bytes are needed. In the slow loop a settle is answered after one pass over the ends even when a read failed (`_outputs.py:252-259`), so a session's turn could settle with bytes still in the pipe, which then land in the next turn's stream. Today that turn says `truncated` because the failure set `dropped` at once. Without the mark it would say nothing. The mark keeps spec 006's promise ("names a stream whose bytes were dropped") on that path and stops naming a stream whose every byte arrived. With 144's line in `_write_output`, both captures follow one rule.

### 7. The flaky row's clock waits for the post it asserts

In `test_a_late_gate_skips_an_async_tool`, the async case's clock moves once the gate has started and the post has been recorded: `Clock(lambda: moved.is_set() and posted.is_set())`. The sync case keeps `Clock(moved.is_set)`, since nothing is posted there. Nothing else in the row changes, and the `posted` fixture does not change: the other rows read it as "the wrapper was handed to the loop", and `Clock(posted.is_set)` there already orders them. No sleep is added. The build has no `gh`, so run 40458869434's log is not read: the landing notes say the cause is inferred from the code and name the line expected to have failed, `assert posts_before_release` in the async case. The one-off reproduction of Decision 8 is the evidence that this line fails when the race is forced.

Reason. Both events are set before the bound may answer, so the row reads `posted` only after it is set: an ordering by events, which is the form the file already uses. A stepped clock is already there; the fault was what it waited on. A seam on the process object would add production surface for a fault that lives in the row.

## Intent

After this specification, no part of a C library table is ever visible to another thread, so two first calls together neither raise `KeyError` nor refuse a guest for an unreadable stack. Every write of the file table's fields goes through the table, and a rule finds one that does not. Every caller outside the platform modules goes through `_platform`, and a rule finds one that does not. No production branch exists for the judge alone in the poll or the call. The pipe reader says when it falls to its slow loop, and names a stream as truncated only where bytes are or may be lost. One unit row stops failing at random.
