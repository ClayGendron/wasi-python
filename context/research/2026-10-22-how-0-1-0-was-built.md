- **Status:** executed (a measurement of this project's own record), 2026-10-22. Nothing in `src/`, `tests/`, `scripts/`, CI, `AGENTS.md` or the constitution changed. No judge, build or CI run was started; GitHub Actions was read with `gh run list` only.

- **Feeds:** the README's "Agentic Development" paragraph and the public page `docs/explanation/how-it-was-built.md`, with its three charts under `docs/assets/how-it-was-built-*.svg`.

## The question

The README says that `v0.1.0` "was developed entirely, and largely unsupervised, by Claude Opus and Fable over the course of one week of near 24/7 continuous development. The estimated total token usage was 13 billion." The owner asked for the analysis behind that sentence: tokens per hour, where the time went (the models generating, builds, the judge, waiting on CI, the owner), and the story of the week. Each part of the sentence is a claim this memo tests: "13 billion", "one week", "near 24/7", "Claude Opus and Fable", and "largely unsupervised".

## Data and method

No other project folder holds this repository's sessions (EXECUTED, `ls ~/.claude/projects/`). (2) `bunx ccusage` 16.1.1 over the same files, as a cross-check. (3) The repository: `git log` (1,255 commits on this branch, 2026-10-16 12:52 to 2026-10-22 13:02), `context/specifications/`, `context/reviews/`, `context/research/`, `context/progress/`, `context/decisions.md`, `CHANGELOG.md`. (4) `gh run list` for every workflow (196 runs; 173 of `release.yml`; `docs.yml` has never run on the default branch).

**What is left out.** The session that wrote this memo (`80c19a46…`, which began at 18:30 on 2026-10-22, after the last commit of the week) and its subagents are excluded from every number. The spike that came before the week ran in another project the day before and is not counted either: ccusage gives that project 1.14 billion tokens and $880 (EXECUTED, `ccusage session`).

**The week.** The first transcript event is 2026-10-16 12:53 and the last (outside this memo's session) is 2026-10-22 14:31, local time (UTC−4). That is 145.7 hours, six days and two hours, not 168 (EXECUTED, `rollup.py`). Every time in this memo is local time.

**Tokens.** One API call is written to a transcript as several records, one per content block, each carrying the call's `usage`. `tokens.py` keeps one row per message id and request id and takes the largest count seen for each field (EXECUTED). ccusage keeps the first record it sees, which carries a partial output count while the call is still streaming; that is why its output total is lower (below).

**Time.** `timeline.py` walks each session's events in order and gives every gap between two events a class (EXECUTED). The rules:

1. A gap that ends at an assistant record is **the model generating**: the API call, from its input to its last block, queueing included. It is capped at 10 minutes; any rest is idle.
2. A gap that ends at a foreground tool's result is that tool's time. A Bash or Monitor command is classed by regular expressions over its text, in this order: **waiting on CI** (`gh run`, `gh pr checks`, `gh workflow run`, a GitHub run id, or a script named for watching a run); **building** (`build.sh`, `scripts/steps`, `scripts/0N_`, `docker run|build|exec`, then, after the judge's test, `build.log`, `make`, `clang` and the like); **the judge and test runs** (`pytest`, a mutation probe, the upstream suites' survey and measure scripts, `lane.lock`, `--tier`); a bare `sleep` is waiting on CI when a `gh run` call is within 15 minutes in the same session, else other. Double-quoted text of 40 characters or more is dropped first, so an acceptance reason that says "build" does not make a judge run a build. `Agent` (foreground) is **waiting on a subagent**; `AskUserQuestion` is **waiting on the owner**; every other tool (Read, Edit, Write, Grep, git, WebFetch) is **other tool calls**.
3. A gap that ends at anything else (a background task's notification, a subagent's hand-back, the owner's prompt, a heartbeat) is waiting on whatever background task of the session was still running at its start, by rank: building, judge, CI, subagent, other. With nothing running it is **idle**.

`rollup.py` then sums, per minute of wall clock, the seconds every session spent in each class, and gives the minute to the class with the most (waiting on a subagent counts only when nothing else ran, since the subagent's own work is in its own transcript). A minute in which no session worked but a `release.yml` run was in progress is **waiting on CI** (90 minutes in all). A minute with neither is **idle**. Two measures follow: **wall-clock hours** (each minute of the 145.7 hours given to one class) and **agent-hours** (every session's time summed, so parallel agents add up).

**Work.** `work.py` counts commits per day from `git log`, a specification as drafted on the day of the first commit that added its file and as landed on the date after "landed" in its Status line, reviews and memos by the date in their file names, accepted judge records by their `at` field, and release runs by `createdAt`, with a run's length from `startedAt` to `updatedAt` (EXECUTED). `owner.py` keeps the owner's own messages to the lead sessions, deduplicated (a message typed while the agent is busy is recorded twice) and without the lane's self-scheduled "Lane heartbeat" prompts (EXECUTED).

**The 13 billion holds, counting cache reads.** The week used 13.23 billion tokens. Without cache reads it used 0.54 billion; the models wrote 9.1 million. A cache read is the model re-reading the context it already had: each turn of an agent re-reads its whole conversation so far, cheaply. The number is real, but it measures how much context the agents carried, not how much they wrote. ccusage, reading the same files, gives 13.27 billion for this project including this memo's session (about 45 million), so the two agree to within that session (EXECUTED, `ccusage session --json`).

**By model.** Claude Opus (`claude-opus-5-5`) made 51,306 of the calls and 13.15 billion tokens (99.4%). Fable (`claude-fable-5-1`) made 262 calls and 71 million tokens (0.5%), all as an advisor: ten subagents named for it, among them the principal engineer's direction (2026-10-17), the prior art on byte-identical builds (2026-10-18), the Rust-core assessment, the pre-import policy, the workflow speed-ups and the wave pipeline (2026-10-19), the test-budget choice (2026-10-20), the process advice (2026-10-22) and the documentation plan (2026-10-22). One security-research subagent ran on `claude-opus-4-8` (42 calls, 6.4 million). So "Claude Opus and Fable" is accurate in kind; in volume it is Opus, with Fable consulted at the decisions that mattered.

## What the numbers do not show

- **Time is approximate.** The classes come from regular expressions over command text. A command that runs a build and then the judge counts as a build; a wait loop on a log file with an unhelpful name counts as other tool calls. Agent-hours of waiting on a background task count the agent as waiting even when it was asleep between notifications, which is what waiting is.
- **"Generating" includes queueing.** The time to an assistant record includes the API's latency and any rate limiting, and it is capped at 10 minutes a gap.
- **A "working" session is not a busy CPU.** The machine's load (the judge at `-n 6`, container builds) is not in the transcripts; the parallelism above counts agents, not cores.
- **CI's own time overlaps the agents'.** 100.4 hours of release runs ran on GitHub's runners beside the 145.7 hours of the week; only 90 minutes of it filled an otherwise idle minute.
- **Subagents killed by the owner** (Wednesday 21, 06:46: "There are some agents then have been running for a long time, so I am going to cancel them") end their transcripts where they stopped; their time counts to that point.
- **Tokens are not cost.** The owner's plan is a subscription; ccusage's dollars are list prices.
- **The specifications' dates** are from file names and Status lines, so a specification drafted on one branch and committed to main later counts on the day it reached this branch.

## Open questions

- Whether the 82% of tokens spent by subagents re-reading context could be cut by shorter briefs or smaller worktrees, without losing the fresh-context reviews that caught real faults. Not measured here.
- How much of the 37 wall-clock hours of judge runs the advisor's "section 2" (reserved after 0.1.0) would save. A measurement for 0.1.1.
- Whether ccusage should be told to keep the last streamed record of a call, not the first: a question for its maintainers, not for this project.
