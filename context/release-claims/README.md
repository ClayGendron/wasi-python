# /context/release-claims

The release ledger: one file per pull request, `NNN-<slug>.toml`, named after its news file (`../changes/NNN-<slug>.md`), holding that pull request's `[[claim]]` blocks in the news files' claim shape (`../changes/README.md`), each with `spec = "NNN"`. Between two releases it carries each reason the release must read whose news file will not be there.

- **Who writes a file.** A pull request that changes a release-tier row, or what one runs, writes its blocks into its own file, since the run after its merge judges the normal tier alone. A later pull request of the same specification adds its blocks to that file, beside its news file. The release's preparation writes the reason for each row an acceptance on `dev` recorded as unclaimed into the file of the change the row belongs to (`../progress/README.md`, *Acceptance from CI's record*). Nobody edits another pull request's block.
- **Why a file each.** Until specification 177 the ledger was one file, `../release-claims.toml`, and every pull request appended its block at the end. Each merge then made every other open pull request conflict, so they merged one at a time. One file per pull request, as the news files are, lets them merge in any order.
- **What holds it.** `ci-status` refuses a pull request into `dev` that adds a block to a file not named after one of its news files, drops a block from another's file, or brings the single file back. `tests/checks/test_rules.py::test_the_release_ledger_is_a_file_per_pull_request` holds every file's name and the single file's absence, and `::test_the_release_ledger_holds_claim_blocks_in_their_shape` each file's blocks.
- **Who reads it.** The release pull request's gather and acceptance read every file here, in file-name order, after the blocks `release/version.py date` moved under the version in `../release-claims-history.md`. `date` moves each file there, under its name, and removes it; this README stays, so the folder does.
