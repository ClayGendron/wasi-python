## Findings, most severe first

1. **Medium: a call or session already running when a file is saved or loaded is not kept from it** (`_snapshot.py:176-204`, `:231`, `_places.py:504-517`; row R2; Decision 8). The grant judge runs when a call or session starts, so a folder remembered later is not judged against the writable grants of calls already live, and `save` and `load` do not ask. Failure (EXECUTED): `Session(grants=[Grant(w, "/w", writable=True)])` opened, then `snap.save(w / "app.wpsnap")`, then a turn writes the bytes of another saved snapshot into `/w/app.wpsnap`; `Snapshot.load(w / "app.wpsnap")` returns it (mode 0600, this user's) and every call from it runs the guest's image. The how-to's sentence "A call in this process refuses a writable grant or root that holds the folder of a snapshot it saved or loaded" reads as covering this case, and Decision 8 names only another process as the case the runner cannot know. Fix text, one of: (a) code: `save` and `load` refuse, with `PermissionError`, a folder that a live call's or session's root or writable grant holds at or above, by identity, from the walked grants the process already keeps for its live sessions and calls, with a unit row; or (b) words, if the owner or the orchestrating session accepts the residual: Decision 8 gains "A call or session already running when a file is saved or loaded was judged before the folder was known, and is not judged again", and the how-to's sentence becomes "A call that starts after you save or load a snapshot refuses a writable grant or root that holds its folder. A call already running is not checked, so save before you start calls that grant that folder writing, or keep the file elsewhere." Evidence that closes it: the row of (a), or the sentences of (b) and the decision's record in the Disposition.
2. **Low: the folders are judged with links resolved at each call, not as written** (`_places.py:511`, row R2). `_judge_snapshot_folders` takes `_chain(folder)`, which follows every link, where the module cache takes `_cache_chain` so that a link on the path inside a writable grant counts (INFERRED: a file saved at `/app/link/s.wpsnap`, `link` a link inside a writable grant at `/app`, leaves `/app` allowed, and a guest may repoint `link` before the next `load` of that path; a planted file still needs mode 0600, so the embedder's umask must be 077). Fix text: "judge each remembered folder by `_cache_chain`, so a writable grant that holds a link on the path as written is refused, as for a module cache."
3. **Low: a loaded file's `home` is taken as given** (`_snapshot.py:352-385`, row R2). Format 1 has one HOME, `IMAGE_HOME`, and `_guest_home` preopens the call's private folder at whatever path the header names. Fix text: "`_header_origin` refuses a `home` other than `IMAGE_HOME` as a damaged header, and a unit row holds it."
