## The seam-scanner decision (Decision 4, item 5)

The question: 108's `RUNNER_MODULE` (`^wasi_python\.(runner|mounts|_\w+)$`, `tests/harness/scan.py:1967`) excludes `tools` by name; the draft extends the exclusion to `_tool_schema` and `_tool_host`. Is that weakening the judge?

**My verdict: it is the rule's own reason, not a weakening.** Three reasons, each from the text that made the rule.

- The rule is about the process state. 108's Design D4 (READ, its specification lines 285–297) says what is outside it and why: "`tools`, `cli` and the package `__init__` (the memo's H5 and 105's rule are about the runner; `tools.py` is the model the memo points at, and its patched names are bounds the judge lowers to reach a limit, `_TOOL_RESPONSE_BYTES` six times, counted by measurement M6, not seams)". The exclusion is by concern; the file name was the only handle the regex had. 108's pre-build review (READ, its M1) argued about who owns the check, not about `tools`, and its verdict let the exclusion stand.
- The letter was written for the runner. `_\w+` stands for "any `wasi_python._<name>` module, which after 104 is the package": the runner's private modules, which at 108's time were the only ones. The tool protocol's text in a `_tool_*` module is the same text the rule excluded, in a new file. EXECUTED: a scratch file with `from wasi_python import _tool_host as H; monkeypatch.setattr(H, "_TOOL_RESPONSE_BYTES", 100)` and the schema's `_key` is two hits under today's regex and none under `_(?!tool_)\w+`; so without the edit the fast tier is red on ten sites 108 itself said are not seams.
- Nothing the judge holds today is loosened. No existing expectation changes (`SEAM_ALLOWED` untouched; no case of `test_scan.py` flips); no runner name becomes exempt; the ten patches are still counted by the rubric's M6 (`grep -rhoE 'monkeypatch\.setattr\(…"_\w+"'`), so the structural review still sees them. The judge's scope is the same set of names before and after; only the spelling of "the tool protocol" changes.

The two alternatives the draft rejects are worse for the right reasons. Adding the five names to `SEAM_ALLOWED` is the weakening the question fears: the list only shrinks, and the stale-allowance logic would then guard tool names under a rule whose reason says they are not seams. Constructor parameters are a design change in a specification that moves text. But the draft's reason against them is partly wrong: a defaulted keyword on `_ToolHost` is exactly the form R6 prefers ("seams are constructor parameters or protocol objects"), not "a branch only the judge takes"; the rejection stands on "a move, not a design change", and the Scope already reserves the response cap as a parameter for later. L6 fixes the words.

Two write-ins make the edit exact (L1): the scanner has a second regex for the dotted-string form, `SEAM_BY_PATH` (`scan.py:1971`), which the draft does not name (EXECUTED: `monkeypatch.setattr("wasi_python._tool_host._TOOL_RESPONSE_BYTES", 100)` is still a hit with only `RUNNER_MODULE` edited); and I recommend spelling the two names (`_tool_schema|_tool_host`) over the prefix `_(?!tool_)\w+`, so the exemption is exactly two modules and a later `_tool_x` module joins it by hand, with a reason, as every other allowance is explicit. Graded: the decision is right; the text needs L1 and L6.
