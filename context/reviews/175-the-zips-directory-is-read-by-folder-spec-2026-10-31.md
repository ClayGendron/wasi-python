2. **Medium: a trigger that fires after `invalidate_caches()` can report a file that exists as missing.** Failure: the program runs `import tzdata`, then `importlib.invalidate_caches()`, then `pkgutil.get_data("tzdata", "zoneinfo/UTC")`. The cached top-level importer's `get_data` fires the trigger while zipimport holds no dict for the zip. The prototype's `load` then raises `KeyError` (`scripts/lazy2.py:83-84`). A load that is skipped instead lets `_get_files()` re-read with only the folders loaded before, and `tzdata` was never loaded, so the answer is `OSError`. `files("tzdata")` fails the same way. Criterion 3's check, two submodule imports, passes either way, because a new importer re-reads before its trigger fires. Fix text, Decision 3: "Every trigger takes the dict through `_get_files()`, the importer's own or the path's loader's, and never from `_zip_directory_cache`. So a trigger after `invalidate_caches()` re-reads first and then loads into the new dict. The pending runs are kept with the dict they were read from." Criterion 3 gains: after `import tzdata` and `invalidate_caches()`, both `pkgutil.get_data("tzdata", "zoneinfo/UTC")` and `files("tzdata").joinpath("zoneinfo/UTC").read_bytes()` as first touches.

**Confirmed after amendments, 2026-10-31:** Fit to build. I re-read the amended specification against each finding. Findings 1 to 8 are taken as their Disposition says (Decisions 1 to 5 and 8; criteria 1 to 5). Two changes go beyond the findings.

- **`START_FACTOR` from 3 to 2 is honest, and the check still guards what it was written for.** The check's docstring (`test_v1_3_data_stack.py:221-225`) asks that a change to the plain start restate the factor as a judge change, and this is that case. The check guards two things: the snapshot's reason to exist, and a package pre-imported by mistake. Today the ratio is about 5.2 (282.2 M against 54.6 M). After 175 it is about 2.9 (113 M against 38.9 M, INFERRED). The snapshot start is recorded, so the ratchet already holds its absolute fuel; the factor holds only the relation. In absolute terms the guard gets tighter. Today a snapshot start can grow by about 39 M before the check goes red (3 × 54.6 M = 163.8 M is under 282.2 M). After 175 at factor 2, it can grow by about 17.6 M (2 × 56.5 M = 113 M). So nothing a pre-import would add gets through that gets through today. An absolute bound would duplicate the ratchet. Factor 2.5 would leave about 16% margin over a plain number that is still projected and that moves with the plain binary's random hash seed. Left open, Low: the comment at `:177-179` and the claim state the measured ratio and both starts, not "about 3.8 times".
- **Importing a package as a fourth trigger is sound.** zipimporter takes `exec_module` from `_LoaderBasics`, so `install()` can set it on the class as it sets `get_data`. A submodule's importer has already loaded its folder, so the hook only acts on a top-level package. A namespace package runs no loader, and `mpl_toolkits` loads on its first submodule as before. The dict only grows, and in the same order as on any other trigger, so no reader sees an inconsistency. Left open, Low: Decision 3 should say the load runs before the package's code, so an `__init__` that reads its own folder finds it. It should also say that importing a package now loads its folder even when its `__init__` imports nothing. For example, `import tzdata` alone costs about 17 M on the plain binary (INFERRED). The zone check's new baseline already holds that cost.
