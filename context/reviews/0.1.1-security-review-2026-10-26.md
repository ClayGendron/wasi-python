### `poll_oneoff` answers as wasmtime does (140; EXECUTED, `p02_poll.py`)

The probe drove the shadow with a fake memory of 64 KiB and crafted subscriptions, outside a guest:

- a count of 0 gives `EINVAL`, 4,097 gives `ENOMEM`, and 4,096 past the memory gives `EFAULT` before any read;
- a misaligned `in_ptr`, `out_ptr` or `nevents_ptr` ends the run with wasmtime's message, as wasmtime ends it;

- each event's padding is written as zeros.

From a real guest with `deadline_s=2`: `select` on a closed descriptor and on stdout for reading give 8; `select([], [], [], 3600)` ends as `deadline`.

### Output through the pipe (129; EXECUTED, `p03_pipe.py`, `p03b_fds.py`)

- **Megabytes.** A guest wrote 48 MiB to stdout and 3 MiB to stderr, interleaved. On the default cap, stdout is exactly 16,777,216 bytes, every byte the guest's, `truncated == ('stdout',)`, and stderr is whole. With `output_bytes=1 MiB`, both streams are exactly 1,048,576 bytes and both are named truncated. The call exited 0 within its deadline.
- **A slow host between two writes.** 8 MiB, then a door call the host answers after 1 s, then 8 MiB more: 16,777,216 bytes, none lost. The reader kept reading while the guest waited.
- **A guest that closes its stdout and stderr.** It printed, closed descriptors 1 and 2, worked, and exited 7, the code it picks when the next write fails. Its first line was kept.
- **A session.** Turn 1 closed both streams. Turn 2 ran and exited 0 with no output. Turn 3's write failed inside the guest. The session stayed usable to its close.
- **Concurrency.** Sixteen calls on eight threads, each writing 20,000 lines of its own id: every call's stdout held only its own lines, and its stderr only its own id.
- **Leaks.** Every capture was a pipe (`on_capture`). After the first round the host held 9 descriptors, and still 9 after 151 more calls, sessions and closed-stdout guests. No `wasi-python-output` thread was left.
- READ: `_PipeCapture` (`_outputs.py:83`) closes the runner's write ends once wasmtime has opened `/dev/fd/N` (`_platform.py:553`), reads with `select.poll`, and never closes an end the guest may still write. Each descriptor is closed once, so I found no double close that could free a number another thread had reused.

## Findings, most severe first

### M1. A guest that opens a host's FIFO in a grant blocks in the host past its deadline, its cancel and `Session.close()`. Medium; the limits; carried from 0.1.0 (EXECUTED, mine)

A FIFO is a named pipe: a file-system object whose `open` for reading waits, in the kernel, until a writer opens it. A guest cannot make one (the audit, EXECUTED). But a host folder the embedder grants may hold one, put there by the host or by another local process that can write the folder.

**What I ran** (`probes/p11_fifo.py`, `p11b_fifo_writer.py`, `p11c_fifo_others.py`, and their logs). The host made `fifo` at 0600 in a granted folder. Each case ran in a child process that the driver killed after 25 s of wall time.

| the guest | `deadline_s=2` | `deadline_s=None`, `cancel` set at 2 s |
|---|---|---|
| `os.stat('/g/fifo')` | returned in 0.5 s, exit 0 | not run |
| `open('/g/fifo', 'rb').read(1)` | **still running at 25 s** | **still running at 25 s** |
| `os.open(..., O_RDONLY \| O_NONBLOCK)` | **still running at 25 s** | **still running at 25 s** |
| `open('/g/fifo', 'wb')` on a writable grant | **still running at 25 s** | **still running at 25 s** |

- **Where it waits.** With a host thread that opens the FIFO for writing after 6 s, `run(deadline_s=2)` returned after 6.0 s as `trapped="deadline"`. So the guest was blocked in the host's open, beyond wasm code. The guest's `O_NONBLOCK` does not reach the host's open.
- **What 128 changed.** With one call blocked this way, another call on another thread finished in 0.05 s. At 0.1.0 the audit's `fifo_modes2.log` shows the other call still waiting at 6 s. A process whose only blocked call is on a daemon thread still exits.
- **What it still holds.** `Session.close()` on a session whose turn is blocked had not returned at 25 s. The call's thread, its store and its descriptors stay held until a writer appears.
- **Why.** The deadline, the cancel and Ctrl-C stop wasm code at its next epoch check. A guest in a host call is beyond them. The `_outputs.py` docstring states this rule for a full pipe, and the reader is built around it. Nothing applies it to `path_open`. The security model lists no special file, and the grants guide names none.
- **Not new.** This is the "one lead" of the 0.1.0 audit's deferred units, a special file of the host's in a granted folder. The audit left it for the owner to read in `agents/h07-*/fifo_*.log` and `agents/h13-*/fifo_*.log`. No specification took it up. SECURITY.md lists "a guest that runs past its deadline" as in scope.
- **Who it reaches.** An embedder whose grant holds a FIFO, or a writable folder where another local process can make one, such as a shared spool or a folder under a shared `/tmp`. The cost is availability: one call, or one session's close, held without bound. There is no escape and no data.
- **Why Medium, not High.** It needs a special file in a folder the embedder chose to grant. The default grants nothing. And 128 keeps it from stalling other calls.
- **Fix:**
  - **The runner** (host-side, `src/`): before forwarding a `path_open`, look at the target without following it, and refuse anything that is not a regular file or a folder with `ENXIO`, as a sealed host would. The runner already counts every `path_open` through its own function (`COUNTED`). A host can still swap the file between that look and wasmtime's open, but a guest cannot. Or open the special file non-blocking, as wasmtime's own WASI would need to.
  - **A row** that plants a FIFO in a read-only and a writable grant, and asserts that the call ends with its deadline and that `Session.close()` returns, seen failing first.
  - **Before the tag at least:** one sentence under *Not protected* in the security model, and one in the grants guide: "A FIFO, socket or device file in a granted folder: opening it can block the call in the host beyond its deadline and cancel."

### L3. The module cache's owner test is still the real uid, where 139 made the folders' and the sweep's the effective uid. Low; the runtime's own files (READ)

### L4. The plan misreads a path that git quotes. Low; CI selection (EXECUTED by the helper, `ci_plan.py:363-365`, `:61-83`)
