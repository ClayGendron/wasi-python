## The package context (EXECUTED and READ)

This is the change that touches more than regex, so I checked it four ways.

**What it touches.** `gen_inittab.py` writes the inittab for the cross-built packages only: 69 entries, numpy's 13, pandas' 45, Pillow's 3, kiwisolver's 1, matplotlib's 6 and regex's 1 (READ, `build/link/inittab.c`). So "every builtin" in the CHANGELOG and README means every cross-built one (finding 3).

**Is it correct.** READ in the pinned CPython 3.15.0:
- `_PyImport_RunModInitFunc` swaps `info->newcontext` (NULL for a builtin) in around `p0()` (`importdl.c:435-437`). Our `ctx_N` runs inside that, swaps the dotted name in, calls the init function and swaps back, so the context is NULL again before CPython's own restore. Nesting is safe: an init function that imports another wrapped builtin saves and restores in turn, and an unwrapped one gets NULL from CPython.
- The context is read in one place, `_PyModule_CreateInitialized` (`moduleobject.c:363`, through `_PyImport_ResolveNameWithPackageContext`, `import.c:911-921`). It renames only when the module's `m_name` equals the last part of the context, and then clears it. Multi-phase modules never reach it in their init function. A single-phase module whose `m_name` is already dotted is left as it is: pandas' `pandas._libs.json` is one (`ujson.c:86`, `:383`).
- A single-phase module with `m_size >= 0` is re-initialised through the stored `p0` (`import.c`, `singlephase.m_init = p0`), which is now `ctx_N`, so a reload gets the context too. That is better than calling the bare init function.
- In 3.15 the context is a `_Py_thread_local` static; the guest has one thread, and the snapshot is taken with it NULL.

**Does it change any existing module** (`probes/modfp_guest.py`, run through the judge's seeded guest with matplotlib's data granted, on both binaries of main's set `s-4eb5418a2b1bb553`, set B and this set). For each dotted builtin: `__name__`; `__spec__`'s name, origin, loader and parent; `__package__`; whether it has `__file__`; whether `sys.modules` holds it; the set of `__module__` values of its classes and functions; and a hash of its `dir()`.
