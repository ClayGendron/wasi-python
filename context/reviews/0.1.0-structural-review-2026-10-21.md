   reserved specification". This is that review, and the closer is still unnumbered.
   Next change it would shape: every new check that needs a seam copies the nearest allowed
   name. `_home._ctrl_c_watched` is already patched 8 times. A change to the store's assembly
   must also be made twice. `_call._instance` (`_call.py:339`, 156 lines without its docstring)
   and `_sessions._open_session` (`_sessions.py:950`, 148) build the WASI config, the scratch
   folder, the mount placeholders, the preopens and stdin in near-identical blocks
   (`_call.py:405–424` against `_sessions.py:1025–1040`).
   Fix: reserve it under the next free number (113 on main at `1875d4cd`, unless another
   reservation took it), with a roadmap line, before the next release. Its scope:
   (a) turn each of the 18 names into the field or constructor parameter its comment names;
   (b) one shared builder for the WASI config and preopens, which takes `_instance` and

2. **Medium: `type: ignore` rose from 12 to 25 with nothing named to bring it back** (`_platform.py:1115–1351`, 14 lines; row R7).
   `pyproject.toml` pins mypy to `platform = "linux"`, so the `_Windows` class's `ctypes.WinDLL`,
   `ctypes.WinError`, `ctypes.get_last_error`, `msvcrt.locking` and `winreg` calls are typed
   only as ignored attributes. The code that runs only on Windows, where a type error would
   reach a user unseen by the Linux and macOS jobs, is the part the type checker does not read.
   Spec 106 called the count "a fact, not a ratchet". The README's ranking makes a measurement
   that moves the wrong way with no specification named a Medium.
   Next change it would shape: the next Windows-only concern adds more ignores by the same
   pattern, and the type checker passes over it.
   Fix: in the same reserved specification, or one of its own, a second mypy pass in
   `test_src_type_checks_under_mypy_strict` with `--platform win32` over `_platform.py`. That
   removes the 14 `[attr-defined]` ignores (the Windows stubs define those names). Record the
   count as a ratchet in that check.

3. **Low: the cache warning is raised under the compile guard, outside the warning queue** (`_platform.py:545`, reached from `_engines.py:143` and `:147` while `guard` is held at `_engines.py:123`; row R8, R3).
   `_Posix.private` calls `warnings.warn` directly. `_process.py:22–24` promises that "the flush
   runs outside every other lock, so an embedder's `showwarning` may take any lock it likes". A
   `showwarning` that calls `run()` on the same thread with the same artifact set re-takes the
   per-digest `compiling` lock, which is not re-entrant, and deadlocks. The same holds for one
   that waits on another thread doing so. This path is unchanged since `30e9b41`
   (`runner.py:4715` and `:4790` there).
   The platform module also writes a user-facing warning's text, which is policy.
   Fix: `PLATFORM.private` returns why the path is refused. `_engines._module_miss` queues the
   text through `_private_dirs`' queue (`process().pending_warnings`), which `runner.py:281`, `runner.py:918`
   and `_sessions.py:494` already flush outside every lock. Add a check whose `showwarning` calls
   `run()`.

4. **Low: `DEFAULTS` is process state outside the process object** (`runner.py:106`, written by `__init__.py:89–90`; row R4).
   `set_defaults` rebinds another module's global under `process().defaults_lock`. The lock
   lives on the owner, but the state does not. The fork reset and the exit release therefore
   cannot see it, and the judge assigns `runner.DEFAULTS` directly
   (`tests/checks/test_v1_4_embedding.py:1413`). The module checks miss this because the value
   is a frozen dataclass, and the mutation is the rebinding.
   Fix: a `defaults` field on `_Process`. `_current_defaults()` and `set_defaults` read and swap
   it, and `runner.DEFAULTS` stays a read-only alias, or is dropped from the docs at
   `tests/checks/test_v1_4_public_api.py:203`.

5. **Low: `_platform.py` stands at 94% of the module ceiling** (`_platform.py`, 1,407 of 1,500 lines; row R5, R7).
   It holds seven OS concerns across four classes, plus the descriptor and path tree removals
   (`_platform.py:554–848`, about 300 lines).
   Next change it would shape: the next platform difference would take it over the ceiling.
   Under this review's ranking, that would be a High: a concern added to a module at its
   ceiling.
   Fix: before such a change, move `_Windows`, `_ByHandle` and the Windows constants
   (`_platform.py:182–205`, `1057–1393`; about 350 lines) into a `_platform_windows.py` that
   `_select` imports. Alternatively, move the tree removal into its own module behind the
   protocol. `_select` and its check stay as they are.

6. **Low: the reaper's and fork's lifecycles are booleans, and two are judge-only branches** (`_process.py:88–89`, `:105–106`, `:111`, `:118–119`, `:164–165`; `_sessions.py:384`, `:410`; row R4, R6).
   The reaper's life is spread over `reaper_thread`, `reaper_stop` and `reaper_hooked`, plus
   `observers.reaper_enabled` and `reaper_paused`. Fork is `fork_used` and `forked`: two flags
   for three states. The memo named the reaper's `enabled` and `paused` flags. They moved onto
   the process object (which the rule permits), but production still branches on them for the
   judge's sake.
   Fix: make the reaper an object whose thread factory and step are injected, so a paused
   reaper is the judge's own driver, not a flag the loop reads. Make fork one enum
   (`FRESH`, `ENGINE_MADE`, `FORKED_CHILD`). This could be part of M1's closer.
