## The approach: reading against refusing

Reading the construction path cannot be complete for arbitrary Python: a metaclass `__call__` or a `__new__` that builds the instance by another route (a factory, a subclass whose own `__init__` is a partial) runs code the walk does not read, exactly as a function's body is not read today (INFERRED). That is the same boundary the function promise already has ("wherever `inspect.signature` may meet one", `tools.py:440-441`), so it is not a new unsafe default. Two things make the read safe as specified: the read is done whatever the metaclass (Decision 1's second paragraph), so a delegating metaclass cannot hide the class's `__init__`; and recording a keyword the metaclass never passes on only refuses more frames, which fails closed (INFERRED). Refusing every class whose construction path holds a partial (Decision 2) would be simpler and equally safe; the specification's choice of reading, with refusal as the named fallback, is sound. What it lacks is the boundary in words (finding 4).

The error types promised are today's: `ValueError` at `tool()` for a given schema naming a fixed keyword (READ, `tools.py:421-424`), `invalid_arguments` per frame (READ, `_tool_host.py:1003-1009`), and `TypeError` for an unbound `partialmethod` or a walk past `_WRAPPER_DEPTH`. Promised by type; the rows match on the keyword's name, which is right.

No legitimate class tool in `tests/`, `src/` or `docs/` is affected by Decision 1: none registers a class as a tool (EXECUTED, grep for `tool(<Capitalised name>`), and the only class tool shape today needs a given schema, since `_type_hints` reads `type.__call__` and fails for a class without a Python metaclass `__call__` (READ, `tools.py:539-548`). Decision 3 is where a regression can come from (finding 1).
