## Spec 049, the public API frozen: no finding (READ, EXECUTED)

049 renames module constants to private names and documents every public name. It adds `defaults()`, `set_defaults()` and `py.typed`, and makes each call read its defaults once.

It renames no `run` keyword. So no old spelling can be silently ignored and drop a limit. A wrong keyword is still a `TypeError` (READ, spec 049 Decision 4; the snapshot).

`set_defaults` (`p13`):
- It refuses anything but a `Defaults` (`None`, a dict, a str).
- `Defaults` refuses a negative cap, a deadline of 0, `True` and 2**63.
- It accepts unlimited defaults (`memory_bytes=None`, `deadline_s=None`), as assigning `runner.DEFAULTS` did in 0.1.0a3 (READ, `v0.1.0a3:runner.py:212`). That is the embedder's own explicit choice, so it is not a new hole.
- A restore brought the 1 GiB cap back: a 1.5 GiB allocation raised `MemoryError` again.
- One read per call, under a lock, removes a mixed read under threads (READ).

## Spec 054, read-only code on the import path: no finding (READ, EXECUTED)

I read `_check_import_path`, `_judge_import_path`, `_import_prelude` and the `--import-path` flag in full, and spec 054's Decisions 1 to 7. Its pre-build and build reviews are in `context/reviews/054-*`.

**Refused before any work** (`p12`), each with a message naming the entry:
- an entry under a private root;
- an entry served by a writable grant, or by a read-only mount;
- a writable grant or a mount lying under an entry;
- a writable host folder, and a root, inside the serving grant's folder, judged by identity;
- `/p2` beside a read-only grant at `/p` under a writable root (no prefix confusion);
- an entry at `/usr/local/lib/x`, an entry with `..`, and a `bytes` entry.

**The prelude cannot be injected.**
- A `str` subclass whose `__repr__` and `__str__` both lie put exactly `/p/lib` on `sys.path`. No injected code ran.
- Guest paths with quotes, a backslash, and the text `') or print('INJ') or ('` were each put on `sys.path` verbatim, and nothing else ran.

**The hostile guest:**
- It saw `sys.argv == ['-c']`, as without an import path. The prelude is not visible.
- Its module from the entry imported and ran.
- It could not write `evil.py` or `__pycache__/x.pyc` into the entry, or into the grant's sibling folder (63 each). The host folder was unchanged afterwards.
- A traceback from `eval('1/0')` did not show the prelude.

**What stays documented, not prevented** (054 Decisions 5 and 6, README):
- An embedder that grants a folder writable in one call and serves it as an entry in another plants code for itself.
- An entry may supply a name the runtime tries and lacks, such as `pytz` or `_hashlib`.

Both are the embedder's own choices of what to serve. Neither gives a guest a way out.
