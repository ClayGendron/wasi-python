## The environment entry (`cpython-c-pydoc-imports-scipy`)

It is an allowance edit, so a judge change (AGENTS rule 4). I checked whether it hides anything.

- **The mechanism is CPython's, not ours.** `pydoc.ModuleScanner.run` calls `__import__` on every name in `sys.builtin_module_names`. Here scipy's 95 compiled modules are builtins, so `test_pydoc`'s apropos tests import them, and with them scipy's Python packages from the zip. Natively they are not builtins, and `test_pydoc` limits `walk_packages` to its own temporary folder, so a native `test_pydoc` imports no scipy. That is why the change shows only here.
- **What scipy's imports do, guest against native** (EXECUTED). One probe imports each scipy builtin by dotted name in sorted order, as apropos does, and records the first module after which `threadpoolctl` and `charset_normalizer` appear, the keys added to `os.environ`, and `len(logging._handlerList)`. In the guest: `threadpoolctl` first after `scipy.io._fast_matrix_market._fmm_core`, `charset_normalizer` first after `scipy.cluster.hierarchy._hierarchy`, `KMP_DUPLICATE_LIB_OK` added, handlers 1 → 3, no failure. Natively, the same probe over the wheel's compiled modules (106 of them, by file) gives exactly the same two first importers, the same key, handlers 1 → 3, and one failure, the `_matfuncs_sqrtm_triu` circular import patch 0002 fixes.
- **The paths** (EXECUTED, a meta-path hook in the guest): `threadpoolctl` comes from `scipy/io/_fast_matrix_market/__init__.py`'s `try: import threadpoolctl` (it registers a controller); `threadpoolctl` sets `KMP_DUPLICATE_LIB_OK` at import. `charset_normalizer` comes through `scipy.cluster` → `scipy._lib._array_api` → scipy's vendored `array_api_compat` → `numpy.f2py` → `numpy/f2py/crackfortran.py` (`try: import charset_normalizer`); its import makes the `NullHandler` and the api module's `StreamHandler`. So "scipy's imports bring in charset_normalizer" is true, by way of numpy's f2py (L1).
- **Scope.** The entry is limited to `test_pydoc.test_pydoc` and to the two kinds of change seen; its gap pins `1 finding(s), digest c1977f2d517b`. A third kind of change, or another module, still turns the check red. Its `closes_with` names 037 itself; nothing in 037 closes it, and as long as scipy (or numpy's f2py) imports those packages at import it stays. `stepped-clock` names spec 002 in the same way, so it passes the rules check; I would say so in the text (L1).

Verdict on the entry: honest. It records native behaviour that the guest shows only because its packages are builtins.
