## What changed, and what held

### The stdlib zip read by folder (175; EXECUTED, `p_zip_table.py`)

The reader runs in the guest, on the stdlib zip alone (`install(by_folder=True)` names `sys._stdlib_dir`), and reads only from that file through one descriptor, at offsets inside its central directory. So a crafted table can at worst give the guest a wrong import, never a host read. The probe loads `recipes/zip_directory.py` on the host, writes a real table with step 70's own `write_folder_table` into a zip of three packages, then replaces the comment with crafted tables: an offset or a size past the directory, a count one more or fewer, a folder named `..` or another folder's name, rows swapped or repeated, an `__init__` offset outside its run, a 4,000-digit number, a negative or a Unicode digit, no final newline, version 2, and 300 random byte flips. Each gave the full read (309) or a dict whose every entry equals the full read's after every folder loaded (7). None raised past `read_directory`, none differed.

READ: `_entries` checks `p + 46 > stop` before each unpack and the name's end against `stop`, refuses Zip64 and cp437, and refuses a member whose data offset is past the directory; `_fits` refuses a loaded run whose count or `__init__` entries differ from what the start read. One edge, a note: a name flagged UTF-8 that is not valid UTF-8, inside a pending run, raises `UnicodeDecodeError` from `_load` at the folder's first use rather than at the start (INFERRED); zipimport's own reader raises the same error at the start. The zip is the set's, hashed in `SHA256SUMS`.

### The end of a call that frees nothing (176; READ, `reactor_main.c:287-560`)

Armed only once `Py_IsFinalizing()` is true, the hook threads freed blocks onto a list through their first word, counts every later allocation by dlmalloc's chunk size (an over-count, saturating on overflow), and drains every list before an allocation would pass `TEARDOWN_BUDGET` (1 MiB) or after one gets NULL, retrying once. A failed `realloc` keeps its block, and `realloc(p, 0)` is never retried. After `run` or `shutdown` finalized, every export refuses, so nothing runs on the stranded lists; a program tracing with `tracemalloc` gets no hook. Every byte of it is the guest's memory, under the store's limit. A use after free in a finalizer reads a list link where natively it reads dlmalloc's: the guest's own fault, as before.

### Output while the guest runs (164)

READ: `_Feed` queues the bytes a stream admits on the reader's thread and posts one delivery to the call's home when none is pending, so wasmtime's thread never runs the embedder's callback. A callback's `Exception` is warned once and ends delivery; any other `BaseException` stops the call. `OutputFeed` refuses a second call. The CLI's `--stream` writes each chunk as a JSON string, so a guest's escape sequences reach the terminal escaped.

READ (helper, and me on `_Stream.write` and `_Feed.add`): the sink gets only the bytes within the cap, once, plus one cut mark, so `_Feed`'s queue and an `OutputFeed`'s deque hold at most the cap per stream between them; the tail buffer wraps in place at the cap. The callback runs on the home thread or on the loop, outside `_Feed.lock`, so no lock is held across the embedder's code (deadlock-freedom INFERRED). A turn's `stdin` is held to `MAX_TURN_BYTES` (`runner.py:1154`), handed through `host_alloc` with its bounds check, and dropped by a second `turn_input`, by `shutdown`, by `prepare` and by `checkpoint(1)`.

### A display frame (163; EXECUTED, `p_display_amp.py`, `p_display_amp_rss.py`)

A call with `results=True` admits a display frame of up to `6 × room + 1 KiB` bytes, `room` being the call's `output_bytes`, and parses it whole with `json.loads` and `_decoded`'s copy before any shape check (`_results.py:149,172`). A frame of empty objects, `{"v":1,"id":1,"op":"display","x":[{},{},…]}`, is refused only after that parse. I drove `_ResultHost` directly in a fresh process, with no tools: at `room` 1 MiB a 6,292,475-byte frame raised the host's peak resident memory by 305 MB, 291 times `room`; at 4 MiB a 25,166,843-byte frame raised it by 1,215 MB, 290 times. Under `tracemalloc` the first peaked at 309,027,211 bytes. The helper ran it end to end on the 174 set, a guest calling `_host.call` with `results=True, output_bytes=4 MiB`: the host's peak rose from 30 MiB to 4,239 MiB, and the call returned exit 0 (EXECUTED, helper). That is H1.

### Checkpoints (162; READ, `reactor_main.c:1172-1240`)

`checkpoint(1)` refuses on the plain reactor, before a turn returned, during a turn, a prepare or a shutdown, after `run`, and while entered; it drops a held stdin and zeros the dead stack. A start from the image forgets its preopens and rebuilds them from its own store, so a checkpoint carries no host descriptor: WASI's table is the host's, outside the image. A turn that left a file open refuses the checkpoint. The image is a `Snapshot`, saved and loaded under 0.1.2's `open_owned` rules.

READ (helper): the image is the guest's memory whole, at most `memory_bytes`, and a `MemoryError` while it is read is caught and the session goes on (`_sessions.py:844-860`). A restore checks a whole number of pages, at least the fresh memory and within the store's limit, and `_check_kind` holds the header's home and parent digest to their patterns. The image holds the session's environment values, though the origin keeps their names alone (L4).

### The packages a set carries (171; READ, `_packages.py`)

`packages()` reads the set's zip on the host. It refuses a `.dist-info` member whose declared size is past 1 MiB, and `zipfile` reads a member only to its declared size. A name, a version or an import name with a control character or a line separator is refused, so a set cannot add a line to the prompt `str(Package)` is made for. A name can still say anything in one line; the set is the embedder's own, trusted as code. The answer is cached only when the file read is the file the key's stamp names.

## Findings, most severe first

### H1. A display frame is parsed whole before it is judged, so the host's memory grows about 290 times `output_bytes`. High; the door, host memory (EXECUTED, `p_display_amp_rss.py`; READ, `_results.py:140-172`, `_tool_host.py:108-150`)

- `admit` lets a display frame through up to `ESCAPE × room + ENVELOPE` bytes (6 × `output_bytes` + 1 KiB; with `output_bytes=None`, no length bound at all). `_answer` then runs the tool host's `_parse`: `json.loads` of the whole text, then `_decoded`, which copies every list and dict, before `_refusal` checks the shape. A frame of empty objects costs the host about 48 bytes per 3 bytes sent.
- Under `tools=`, a frame that is not a display is parsed here too before the tool host's 1 MiB cap is applied, since `admit` lets through the larger of the two bounds.
- Failure: an embedder runs untrusted code with `results=True` and the defaults; the guest sends `{"v":1,"id":1,"op":"display","x":[{},{},…]}` of 96 MiB → the host's process grows by about 4.7 GB before the frame is refused, and is killed by the system where memory is short; a guest can repeat it, and two sessions double it. The rubric's "every channel to the host is bounded" (R2) holds only in name.
- **Fix:** bound the parse, not only the length. Before `json.loads`, in the one pass `_nesting` already makes, count the values outside strings (each `[`, `{` and `,`) and refuse a frame with more than a small number, say 64 (a display is at most six MIME types, a `value` flag and six cut types), as a `protocol` refusal; and in `admit`, give a frame past the tool host's cap only to the display path, so a tool frame is never parsed past 1 MiB. Add the frame above to the hostile-guest checks, with the host's peak growth counted against a bound of a small multiple of the frame. A frame of one long string stays allowed: it costs about its own length.

### M1. A tag whose wheel passes 100 MiB signs and publishes on GitHub, then fails at PyPI. Medium; the release path (READ, `release.yml:1582,1616,1659`; `tests/harness/artifacts.py:245`; `release-process.md:32`; 174's landing notes)

- The wheel's check now allows 268,435,456 bytes (091), and runs in the judge, which a tag's run does not run. The wheel was 104,899,641 bytes at 174, past PyPI's default 104,857,600, and 169 and plotly add to it.
- The tag's jobs run `attest` (a signature, permanent in the public transparency log), then `publish` (the GitHub release), then `pypi`. Nothing between the tag and `pypi` compares the wheel with the limit PyPI has granted.
- The guard is the decision's sentence ("No release is tagged for PyPI with a wheel past 104,857,600 bytes until PyPI's answer is recorded here; the owner tags") and the maintainer's comparison by hand (`release-process.md:32`).
- Failure: the owner tags `v0.1.3` with `PYPI_PUBLISH` true before PyPI's grant is recorded, or reads the wrong number → the provenance is signed and the GitHub release made, then PyPI refuses the file; 0.1.3 stands on GitHub and not on PyPI, and `pip install wasi-python==0.1.3` fails for every embedder.
- **What closes it:** a step in `judged`, or a job `attest` needs, that fails when `vars.PYPI_PUBLISH == 'true'` and the wheel is larger than a repository variable holding the granted limit (default 104,857,600); or `pypi` before `publish` and `attest`. Until then, the release pull request's description records the wheel's bytes and PyPI's recorded grant, and the owner tags only when the second is the larger.

### L4. The security page says nothing of a checkpoint. Low; documentation (READ, `security-model.md:84-91`; `snapshots.md`'s checkpoint section)

- A checkpoint holds every byte the session read, from grants, mounts, tools and its environment's values (the origin keeps the names alone), and gives it to every start from it and to whoever holds its file. The how-to says so plainly. "Reused roots and state across calls" names a session as one trust domain and a saved snapshot's file, but not a checkpoint.
- Failure: an embedder who reads the security page alone checkpoints a session that read a secret and starts a less trusted program from it → that program reads the secret, whatever its own grants say.
- **Fix:** one bullet under "Reused roots and state across calls": "A checkpoint carries everything its session read, to every start from it and to whoever holds its file; start one only where that code may read it all", linking the how-to's section.

### L5. cairo's MPL-1.1 source is offered only at its upstream address. Low; licences (READ, helper, `assemble_artifacts.py:492,893-903`; INFERRED)

- MPL-1.1 §3.2 asks a distributor of the executable form to keep the source available for at least twelve months. The notice points at cairographics.org, a third party's host.
- Failure: cairographics.org removes 1.18.6's tarball within the year → the release's source offer lapses.
- **Fix:** attach `cairo-1.18.6.tar.xz` to the GitHub release, as the test-source mirror already holds release assets, or record the owner's acceptance of the upstream address in the decision.

### L6. 0.1.1's L1 stands: `ci-status` is computed by the pull request's own code. Low; carried (READ, `release.yml:120,144`)

- The plan runs `release/ci_plan.py` from the pull request's head, so a pull request that edits it can give itself an empty refusal list. The owner's merge and the post-merge run on `dev` remain the guard, as at 0.1.1 and 0.1.2.
- **Fix:** as 0.1.1 named it: run the refusal logic from the base branch, or a code-owner rule on `release/` and `.github/`.

### L7. The guest's `poll_oneoff` wrapper multiplies a count without a check. Low; guest-only robustness (READ, helper, `reactor_main.c:137`; INFERRED)

- After a checkpoint's restore sets `monotonic_offset`, the wrapper copies the subscriptions into `malloc(count * sizeof *copy)`; a count past about 89 million wraps on wasm32, and the copy writes past the block.
- Failure: guest code (through cffi, or a C extension) calls `poll_oneoff` with such a count in a start from a checkpoint → the guest's own heap is overwritten, and the call traps or misbehaves; the host is not reached, since every write is in linear memory.
- **Fix:** return `__WASI_ERRNO_INVAL` when `count > SIZE_MAX / sizeof *copy`, before the `malloc`.
