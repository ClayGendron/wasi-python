## The questions the brief asked, answered first

1. **Decision 3, Linux needs no list read.** Right, in every case asked. `acl(5)` ("VALID ACLs") requires exactly one `ACL_MASK` entry once an `ACL_USER` or `ACL_GROUP` entry exists, and the kernel's `posix_acl_valid` refuses a list without it (INFERRED, the kernel's model). Its "ACCESS CHECK ALGORITHM" grants a named user, a named group **and the owning group** (`ACL_GROUP_OBJ`) only the rights both its entry and the mask hold, and "CORRESPONDENCE BETWEEN ACL ENTRIES AND FILE PERMISSION BITS" makes the group class bits the mask's while a mask exists, else the owning group's. So with a mask, any write a non-owner entry grants is `w` in the mask, which is `w` in `st_mode`'s group bits; with no mask the list is the three mode classes (the kernel stores none, `posix_acl_equiv_mode`), and the group bits are the owning group's. `ACL_OTHER` is the other bits, `ACL_USER_OBJ` the owner, whom the walk already trusts or refuses. A default list (`system.posix_acl_default`) is not evaluated on the folder it sits on; `acl(5)`'s "OBJECT CREATION AND DEFAULT ACLs" cuts a new folder's inherited access mask (or owning-group entry) to the `mkdir` mode's group bits, none at 0700, so the folders `cache_folder` makes grant nothing, and the cache folder made below one inherits a list that 135's presence test refuses. Removing or renaming a child needs write and search on the folder (`unlink(2)`, `rename(2)` `EACCES`), with the sticky bit's owner rule; Linux has no per-object delete right, so the folder's own rename is its parent's `w`, and the parent is on the way. One precision the specification may add: a `w` with no `x` grants nothing on a folder, and the walk refuses it anyway; that is the mode rule's strictness, as today.
2. **Decision 1's macOS set.** Complete for the threat through the userland API, and not over-broad. `delete_child` is the swap; `delete` on the folder is its own rename (the kernel asks `DELETE` on the source, or `DELETE_CHILD` on its parent, and add on the target); `writesecurity` and `chown` give their holder the rest; `add_file` and `add_subdirectory` mirror `w`. The uncounted rights change no entry: `writeattr` is times and the like, `writeextattr` attributes, and the mode and flags need `writesecurity` (INFERRED from xnu's `vnode_authattr`). One gap at the kernel level: an entry carrying the generic bits, which `acl_set_permset_mask_np` refuses (EXECUTED) but a network file system's translated list can carry, grants every write right with none of the six specific bits set (L1). Principals: every group and `everyone` counted, this user and root passing, an unnamed principal counted, is the mode rule's trust exactly. Inherited entries count and only-inherit entries do not, as xnu's evaluation skips `KAUTH_ACE_ONLY_INHERIT` (INFERRED); the probe of `limit_inherit` shows why the first half matters (M1). Every default folder on the way passes: the five home folders above carry only a deny, and `/`, `/Users`, `/private/tmp`, `/Library/Caches`, `/var/folders/...` and `$TMPDIR` carry none (EXECUTED).
