# c01-critic notes: reasons for resolved leads

- Deep-recursion host entry: covered by the _wasmtime_ffi/_home unit (h08). It checked from source that guest threads start with 10 MiB and that body() refuses below 9 MiB (_home.py:288-298, _platform.py:155-163: _HOST_ROOM 2 MiB against measured callbacks of at most 48 KiB). It checked that a host_alloc re-entry below wasmtime's limit traps at once. Locally it ran 3.8 M door hand-offs and stack-overflow, fuel and deadline traps, each followed by a normal call. h05 showed that the shipped host_alloc is malloc only (hostmodule.c:27-30), so the RecursionError abort needs a custom artifacts= module, which is embedder-trusted.
- gather.py: covered by the release.yml unit (h10), whose reviewed_paths include gather.py. The trust-relevant rules are short and were read: G1 binds records one-to-one to the handed SHA-256s, with no extra file (gather.py:146-178); G2 binds each record's artifact and set_sums to the build's outputs (180-200); G7 binds the build's python.wasm and set_sums to the newest accepted history line, and on a tag also the judge hash and set_source == built (369-386). G3-G6 judge test outcomes. context/progress and the tagged commit have one writer, the owner, the same principal that controls the workflow, so they are not a lower-trust input.
- _write_output: named in the h08 unit's surface ("the output callback"), with checks on key lifetime (a late write or free is harmless), never raising (catches BaseException), and the copy-before-cap hardening note. data and size are host pointers that wasmtime supplies after it has read the guest's iovecs, not guest pointers.
