The one mutable global, the stack pointer, is back at its initial value after every export (the spike, §1.1, EXECUTED there), so memory alone is the state (INFERRED).
2. **The refusals** — a guest cannot reach any export: a wasm export is called by the host alone; the guest's Python reaches C only through builtin modules, none of which calls `reactor_prepare`, and the guest has no `ctypes` (`reactor_bootstrap.py:20`); the door is an import, whose host the runner gives no handle on the instance (READ, INFERRED). The cost is right: real metadata, real directory times and inodes in the image, so an image is the same bytes only when made again in one process from the same folders (Finding 9 for the fresh root).
4. **`_refresh`'s three reseeds** — the first two are right: `tempfile._name_sequence = None` makes `_get_candidate_names` build a new `_RandomNameSequence`, whose `rng` seeds from entropy (`tempfile.py:227-240`, READ); `sympy.core.random.seed()` reseeds both `rng` and `_assumptions_rng` (`sympy/core/random.py:44-46`, READ). The upstream prefix and the 1% rule's wording are Finding 7.
7. **Decision 5, the end of a call** — `gc.get_objects()` walks the three generations and not the permanent one, and `gc.freeze()` merges all three into it (READ, `gc.c:1705-1743`; EXECUTED on 3.14.10). ## Findings, most severe first

1. **Medium: `prepare` sets no flag before Python runs, so a trapped or re-entered `prepare` leaves an instance every export accepts** (Decisions 3 and 4; `recipes/reactor_main.c:485-490` is the precedent it departs from). `turn` sets `turned` and `in_turn` before any Python, so a trap or `proc_exit`, which unwinds without running C, leaves every later export refused (`reactor_main.c:136-139`). `prepare` sets `prepared` only after a prelude returned 0, and nothing during it. Failure: an embedder in another language, the reader Decision 10 writes for, calls `prepare` with a prelude that runs out of fuel, then calls `run` on the same instance: `run_called`, `turned` and `prepared` are all 0, so `run` calls `_reactor.run` over an interpreter whose C frames were unwound mid-call; equally, a host that re-enters the instance from its door during a prelude can call `run` or `prepare` inside it (INFERRED; the runner does neither, so this is the export's contract, not the runner's). Evidence that closes it: a static `preparing`, set before the buffer is copied and cleared just before `prepare` returns; `run` returns 70, and `turn`, `shutdown` and `prepare` return -1, while it is set; a row in `test_v1_4_prepare.py`, `test_a_trapped_prepare_leaves_nothing_callable`: a prelude that loops with a small fuel cap traps, then `run` returns 70 and `prepare` and `turn` return -1, each with no output.
2. **Medium: the making's import path stays on the image's `sys.path`, so a call from the image imports from guest paths no check has judged for that call** (Decision 3, step 3, first sub-bullet). `_reactor.prepare` puts each argv entry that begins with `/` on `sys.path`; nothing takes it off, and `_reactor.run` does not rebuild `sys.path` (`reactor_bootstrap.py:140-205`, READ). The runner refuses an import path served by anything writable, a mount or the root, and any writable folder inside it (`src/wasi_python/_places.py:176-231`, `:503-524`, READ), because code one call plants there would run in the next (spec 006). A call from an image never passes that check for the image's entries. Failure: an image made with `import_path=["/src"]` from a read-only grant; later calls from it with `root="/srv/box"` (a kept root) or a writable grant at `/src`; one call writes `/src/mylib/extra.py`, and the next call's `import mylib.extra`, or any module not yet imported that the zip lacks, loads it. Evidence that closes it: `_reactor.prepare` saves `list(sys.path)` before the prelude and, on every path, restores it and drops each `sys.path_importer_cache` key not on it; modules already imported stay imported; a call that imports more of the embedder's code passes `import_path` again, judged as today, and 150's how-to says so in one sentence; a row in `test_v1_4_prepare.py`: an image made with a read-only grant at `/a` on the import path, and a restored `run` of `-c import sys; print('/a' in sys.path)` prints `False`.
3. **Medium: choice A's reason misstates spec 073's promise, and A gives up finalizers a cheap step keeps** (Decision 5, the recommendation; `tests/checks/test_v1_4_embedding.py:167-169`). The recommendation says "A keeps what spec 073 promised `run`"; the row at `:167` promises more than bytes: "a ZipFile left open is finalized (its directory written)". A loses that for every call from an image, and no row says so. Most such objects are held only by the call's own `__main__`. Clearing the fresh `__main__`'s dictionary drops them by reference count, and `gc.collect()` then walks only the unfrozen generations, so it costs the call's own objects, not the image's (EXECUTED on 3.14.10: a `ZipFile` in a cleared dict, then `gc.collect()`, is a readable zip, the freeze intact). Fix text, Decision 5's mechanism of A: "1. `atexit._run_exitfuncs()`. 2. The call's own names are dropped: in a call, every name of the fresh `__main__`; in a session, every name of `__main__` not bound to the same object in `_MAIN_NAMES`; and `sys.last_exc`, `sys.last_type`, `sys.last_value` and `sys.last_traceback`; then `gc.collect()`, which walks only the generations made since the image was frozen, so `__del__`, `weakref.finalize` and a `ZipFile`'s directory run for what the program alone held. 3. The walk of Finding 4. 4. `sys.stdout.flush()` and `sys.stderr.flush()`." The table's row "what a program loses" reads "the finalizers of objects still reachable from the image's modules (a file a program hung on `numpy` or a module it imported is flushed, not finalized)"; the recommendation's sentence reads "A keeps spec 073's promise for what the program's own names held: its bytes, and a `ZipFile`'s directory"; criterion 5 records the collection's share beside the walk's; a row `test_a_prepared_call_finalizes_a_zipfile_left_open` mirrors `:167` from an image. The documentation's sentence narrows to match.
4. **Low: the walk flushes once, in the collector's order, so a writer stacked on another loses what its flush pushes down** (Decision 5, step 2). `gzip.GzipFile` holds its own `io.BufferedWriter` over the file's (EXECUTED); flushed lower first, one pass left the file at 12 bytes and a second at 16,404 (EXECUTED). Fix text: "each text wrapper is flushed, then each buffered writer, and the writers' pass is repeated while a pass flushed any byte, at most three passes"; and the table's "its bytes so far are flushed" reads "what its buffers hold is flushed; what a compressor holds is not, so a `gzip` or `zipfile` stream is cut short".
5. **Low: the builder's search for the other generators cannot see them as written, and looks for one type only** (Decision 6, third bullet). After a prelude, `prepare` freezes the heap, and `gc.get_objects()` does not list the permanent generation (READ, `gc.c:1715-1721`), so a walk "after the everything prelude" in the image finds nothing it froze. A `numpy.random.Generator` or `RandomState` a package makes at import is not a `random.Random`. A `random.SystemRandom` (`secrets._sysrand`, `secrets.py:20`) is one, and needs no reseed. Fix text: "The builder finds them by a walk of `gc.get_objects()` run as the last lines of the everything prelude, before `prepare` freezes it, for instances of `random.Random` that are not `random.SystemRandom`, and of `numpy.random.Generator`, `numpy.random.RandomState` and `numpy.random.BitGenerator` other than numpy's global one, with `gc.get_referrers` naming each one's owner".
6. **Low: the ending flushes two C streams, not all of them** (Decision 5, the C side). Fix text: "then `fflush(NULL)`" in place of "`fflush(stdout)`, `fflush(stderr)`" in a prepared instance's ending.
7. **Low: the upstream rows' prefix names no check, and the 1% rule is ambiguous** (Decision 9).
