## Findings, most severe first

1. **The Windows escape reaches every call, not only "a guest given any host folder"** (the Problem, the first CHANGELOG line, Decision 8's `SECURITY.md` text, the advisory draft's Impact and its first Workaround). Every call preopens a host folder of the runner's own: the stdlib folder, read-only at `/usr/local/lib` (`_call._preopens`, `_call.py:227-234`; `_zip._zip_folder` makes it a private host folder), matplotlib's data beside it, and, with no writable `/tmp`, an empty private HOME, read-only (`_guest_home`, `_call.py:332-343`). `root=True` adds a writable private root (`:243-251`). (READ.) So on 0.1.5 on Windows a call with no grants at all can read `/usr/local/lib/C:secret`, which wasmtime 50 resolves against drive C's current folder; a call with `root=True` can write there too (INFERRED). The draft's workaround, "Give the guest no host folders", is unsafe advice: it leaves the reads open. Failure: an embedder who reads the advisory gives no grants and believes the host's files are safe. High: a wrong answer in the security record. What to change: the Problem, the CHANGELOG line and `SECURITY.md` say every call on Windows could read through the runner's own read-only folders, and write through a writable grant or root; 3a gains a call with no grants (reads through `/usr/local/lib` and through HOME's folder) and one with `root=True`; the advisory draft's Impact says the same, and its only workaround is upgrading (narrowing every drive's current folder reduces what is reached and stays a note).
