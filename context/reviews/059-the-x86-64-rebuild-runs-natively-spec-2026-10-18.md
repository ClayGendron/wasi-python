## Findings, most severe first

1. **F1 (medium): the "no compile can miss it" check forbids one spelling, and several others override the file.** (Decision 4, `test_every_compile_contracts_nothing`; Decision 2's gate.) The static and compile-records parts reject only the string `-ffp-contract=`. On a command line after the file, `-ffp-model=precise` gives `-ffp-contract=on`; `-ffast-math`, `-Ofast`, `-funsafe-math-optimizations` and `-ffp-model=fast` give `fast`; `--no-default-config` drops the file (EXECUTED, `-###`). The Makefile part reads five variables only (`CFLAGS`, `CONFIGURE_CFLAGS`, `CONFIGURE_CFLAGS_NODIST`, `OPT`, `BASECFLAGS`) and misses `CFLAGS_NODIST`, `EXTRA_CFLAGS`, `PY_STDMODULE_CFLAGS` and configure's per-module `MODULE_*_CFLAGS` lines. Failure: a later package's `meson.build` or Makefile adds `-ffp-model=precise` (a common "strict IEEE" choice). The numpy file then compiles to `20ef3344…` on arm64 and `d3689743…` on x86_64 again (EXECUTED: exactly the old pair). The new check stays green. The first sign is a `same-bytes` failure in CI, possibly after the emulation has been deleted. Fix: forbid the family, not one spelling: `-ffp-contract=`, `-ffp-model=`, `-ffast-math`, `-Ofast`, `-funsafe-math-optimizations`, `--no-default-config`, `--config`; scan the whole CPython Makefile, not five lines; make the gate require that the `-cc1` line holds `-ffp-contract=off` once and no other `-ffp-contract=` value (not only "no `on`"). The step-10 gate cannot see per-compile flags, so the judge's record scan is the only guard for them.

2. **F2 (medium): "the arithmetic does not change" is false for constant-folded expressions, and the stop rule built on it misfires.** (Decision 1, last bullets; Decision 6, "Never `--accept-fewer-passes`"; criterion 4.) LLVM folds `llvm.fmuladd` with constant operands as a *fused* operation (one rounding), while wasm32 evaluates it at run time as a multiply and an add (two roundings). EXECUTED with the pinned clang, `-O2`: `static double g(a,b,c){return a*b+c;}  double h(){return g(0.1,10.0,-1.0);}` returns `0x1p-54` under the default `on` and `0x0p0` under `off`; the `long double` version likewise (`0x3F8D…` against 0). At run time the same expression gives 0 either way. So the flag *can* change results, wherever inlining and propagation folded an `a*b+c`. It changes them toward what the run time computes, which is good, but the spec says it cannot happen. The guard also cannot prove the claim: the goldens print floats to nine digits (`tests/jobs/numpy_random.expected`, `jobs.compare`), and upstream suites mostly use tolerances. 023's pixel goldens may be stricter. Failure: a golden or an upstream test moves in its last bit. Decision 6 says the memo is wrong and the build stops (two strikes). The builder either stalls a correct change or is tempted to edit a golden without a stated reason. Fix: restate the claim narrowly: results computed at run time do not change; values the compiler folded change from one rounding to two, the same value the run time gives. Write the disposition: a moved pass or golden is traced first; if it is a fold, it is the flag's intended effect, recorded with the before and after values, and the golden changes as a judge change with its reason (`--accept-judge`); anything else stops the build as written.

3. **F3 (medium): the fallback is not one line, and the rule check as written forbids it.** (Decision 3 "Switching the fallback on is one line", Decision 4's first and last bullets, Decision 9.) Decision 4's first bullet requires every key's `COMPILER_SDK_DIR` to equal its own SDK; its last bullet allows a different SDK when the switch is thrown. Read literally, throwing the switch turns `test_every_host_compiles_natively_with_the_fallback_kept` red. Decision 9 also needs the workflow timeout back to 360 and `scan.REBUILD_TIMEOUTS` changed. And the fallback with the flag is never run: criterion 3 builds natively only. Failure: the dry run fails on `ubuntu-24.04`; the "same-day, one-line" fallback needs a rule-check rewrite on the day, under pressure. Fix: write the first bullet as "equal to its own SDK, unless the last bullet's switch holds". List the fallback's exact change set (the `line.conf` line, the workflow's `timeout`, `REBUILD_TIMEOUTS`, `--accept-judge`). Add one cheap execution: step 10 alone, in the `linux/amd64` container, with the switch thrown, showing the gate's emulation probes and both new gate lines pass through the emulated clang. That proves "the fallback is runnable" in fact, not only by text.

4. **F4 (low): compiles that leave no record are covered only by what the scripts write.** zlib and xz (autoconf and make), bzip2 and SQLite (direct), step 60's reactor compile, 023's step 37 (qhull) and step 55 (Pillow, kiwisolver), and 037's OpenBLAS `make` leave no `compile_commands.json`. The static part reads flags written in `scripts/`; flags an upstream `configure` or Makefile adds are unseen. A missing record also only lowers the count printed. Fix: derive the expected records from the recipe (each `recipes/*.cross` has its build folder; each must exist when any does, else `blocked`); scan the generated Makefiles of the autoconf builds (`build/xz-build/Makefile`, zlib's) for F1's family; and say that a later make-based build (037's OpenBLAS) brings its own record (for example `make -n` saved under `build/`) into this check when it lands.

5. **F5 (low): source pragmas override the file per block.** `#pragma STDC FP_CONTRACT ON` and `#pragma clang fp contract(on)` bring `llvm.fmuladd` back under the edited file (EXECUTED). None is in a compiled file today or in 023's trees (EXECUTED grep; CPython's mpdecimal `float_control` is MSVC-only; OpenBLAS 0.3.34's are `contract(off)` in non-wasm kernels). Fix: either name pragmas in the spec as out of the check's reach, with `same-bytes` as the backstop, or add a scan of the unpacked source trees for `FP_CONTRACT ON` and `fp contract(on|fast)`.

6. **F6 (low): the zip is probably not one of the hashes that move.** Decision 6 says it moves because `_sysconfigdata` records `CFLAGS`. With the configuration-file route the flag never reaches `CFLAGS` (it is not in the Makefile; READ), so the zip is expected unchanged (INFERRED). The Kind line and the CHANGELOG plan say "every artifact hash changes". Fix: expect `python.wasm`, the snapshot, `MANIFEST` and `SHA256SUMS` to move and the zip to stay, and keep "the builder states why" for either outcome. Related: since `sysconfig` will not show the flag, the README sentence should say that it lives in the toolchain's configuration files and nowhere in the recorded flags.

7. **F7 (low): spec 040's amendment covers one decision, and its last-resort fallback is dropped silently.** Decision 9 changes 040's Decision 11 (the fallback becomes the switch; the 240-minute trip-wire and 360-minute limit stop applying to a native job), and Decision 3 changes 040's Decisions 4 and 6, but the amendment line goes under Decision 2 only. 040's own fallback (x86_64 out of the gate, by one reviewed change) is no longer named: if the emulated fallback also fails, nothing says what is next. The owner's decision says 059 "changes specs 012 and 040's decisions"; the spec says 012's text stands without saying why. Fix: amendment lines under 040's Decisions 2, 4 and 11; keep "x86_64 leaves the gate" as the step after a failed switch; one sentence on why 012 needs no amendment.

8. **F8 (low): spec 057's rebase list is short by two places.** Besides Decision 4's sentence, 057's Scope bullet ("The arm64 Linux wasi-sdk shared by both rebuild jobs") and its F2 disposition say the arm64 tarball runs on both legs. A native x86_64 leg removes that shared input. That is a security gain worth one line in 057's rebase: each leg then runs only its own host's compiler.

9. **F9 (low): the pre-landing evidence for x86_64 is Rosetta only; say what happens between landing and the dry run, and what "the first release" means.** Criterion 3 runs the whole three-host build locally, which answers "all three hosts, the whole set" (good: 040 showed the compiler is the only variable, and the flag changes code in every file, so only a full build can show no new difference). Real `ubuntu-24.04` is first seen after landing. A tag run in that window would fail at `same-bytes` and publish nothing, but it would spend an alpha's security review. Fix: no alpha tag between landing and a passing dry run; and say whether an alpha tag counts as "the first release" that starts the emulation's deletion.

10. **F10 (nit): write both trees' files when the emulation is on.** With the switch thrown, step 10 writes `$CSDK`'s files only; `$SDK`'s stay unedited and unread (every name leads to the launcher). Writing both, and gating both, costs a line and removes a case a later reader must reason about.
