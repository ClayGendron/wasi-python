# Weak definitions that more than one archive of python.wasm's link defines, each read by a review
# and allowed (spec 044, Decision 6; scripts/weak_duplicates.py, run by step 60 before the link).
#
# One pattern per line, and on the same line `# <reason>`: which pinned header the code comes from,
# which archives compile it, and why their copies are the same code (one header, one pinned
# version, one compiler and one set of flags, so one definition). A pattern is fnmatch, against the
# symbol's name and its demangled form, or `scope:<pattern>`, against a C++ name's outermost scope
# (its namespace or class). A pattern without a reason stops the build, and so does a pattern that
# matches no weak definition of the link, so this list never outlives what it allows. A line that
# starts with `#` is a comment.
#
# Allowed by rule, never listed here: the C++ standard library (a mangled name whose outermost
# scope is std::, with its vtables, type information, guard variables and the lambdas inside its
# functions), the C++ runtime's __cxa_* and __cxxabiv1::, and clang's __clang_call_terminate.
#
# Never to be listed: a weak definition with C linkage whose copies differ, or that keeps state of
# its own file, as scikit-learn's bounded_rand_int does (svm/src/newrand/newrand.h); such a name is
# renamed per file instead (recipes/sklearn-renames/). Each C-linkage entry below says why it is
# neither.
#
# The first link with this gate (spec 044's build, 2026-10-20) found 1,186 such names in 270
# archives, all but one from packages already on main; scikit-learn's one, a lambda inside
# std::vector<int>::emplace_back in _hashing_fast and _vector_sentinel, is the std:: rule's.

# pybind11 3.1.0: header-only, from the pinned pybind11-3.1.0-py3-none-any.whl that steps 55 and 57
# unpack, compiled into contourpy, seven matplotlib modules (_backend_agg, _c_internal_utils,
# _image, _path, _qhull, _tri, ft2font) and six scipy modules (fft._duccfft.pyduccfft,
# io._fast_matrix_market._fmm_core, optimize._highspy._core and _highs_options, optimize._pava_pybind,
# spatial._distance_pybind).
scope:pybind11  # pybind11 3.1.0's templates and inline functions (include/pybind11/*.h): the same header text, compiler and flags in every module, so the same code; their function-local statics (the internals instance and its key) become one copy for all modules, as pybind11's capsule in builtins already makes one internals for every module of one version
scope:pybind11_meta_dealloc  # a lambda inside pybind11_meta_dealloc, which pybind11 3.1.0 defines `extern "C" inline` at include/pybind11/detail/class.h:209: one header, one definition, in the same fourteen modules
pybind11_*  # C linkage, by pybind11's design: the thirteen `extern "C" inline` type slots of pybind11 3.1.0's include/pybind11/detail/class.h (pybind11_static_get at :50 to pybind11_releasebuffer at :726), the same inline code in each of the fourteen modules; each works on the objects it is passed and keeps no state of its own file
